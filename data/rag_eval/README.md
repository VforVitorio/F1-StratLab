# data/rag_eval

Versioned RAG retrieval evaluation sets for the FIA Sporting Regulations. Every ground-truth article and keyword is checked against the source PDF named by `source_pdf`.

## Files

- `queries_v1.json` - historical 15-query notebook set and its original schema.
- `queries_v2.json` - canonical 30-query set for `f1-eval rag`, with season, category, source PDF, article, and verified keywords.
- `queries_2026.json` - five 2026 delta queries used by the #323 chunking A/B experiment.
- `results_v1.md` - historical report generated by `N30B_rag_benchmark.ipynb`; it remains for comparison with the original three-configuration experiment.
- `documents/eval_reports/rag.{md,json}` - current shared-harness report generated by `f1-eval rag`.

## How to regenerate the current report

```powershell
uv run f1-eval rag
```

The command runs the production BGE-M3 retriever twice over `queries_v2.json`: once with the requested season filter and once without it as a wrong-year control. It writes `documents/eval_reports/rag.md` and `documents/eval_reports/rag.json`. It does not call an LLM.

The 2026 refresh experiment uses both query sets and builds its candidate index in a temporary directory. It never replaces the production collection:

```powershell
uv run python scripts/benchmark_rag_chunking.py
```

The experiment keeps the 512/64 article-aware baseline unless the 1024/128 candidate preserves P@5, MRR, citation match, and wrong-year safety while improving at least one quality metric.

## Adding a new query

1. Open the relevant FIA Sporting Regulations PDF in `data/rag/documents/`.
2. Locate the article the query maps to and copy its section identifier.
3. Confirm each keyword against that article after accounting for PDF line wrapping. Do not invent ground truth from a model answer.
4. Add the object to a new query-set version with a fresh `id`, `source_pdf`, and the existing ground-truth fields.
5. Run `uv run f1-eval rag` and review both the JSON and Markdown report before committing.
